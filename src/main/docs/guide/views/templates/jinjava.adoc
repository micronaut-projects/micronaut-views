Micronaut Views Jinjava includes api:views.jinjava.JinjavaViewsRenderer[] which uses
https://github.com/HubSpot/jinjava[HubSpot Jinjava], a Java implementation of the Jinja template language.

Add the following dependency to your classpath:

dependency:micronaut-views-jinjava[groupId="io.micronaut.views"]

Templates use the configured Views folder (by default, `src/main/resources/views`) and the `.jinja` extension.
The renderer supports Jinja inheritance, imports, and includes. Referenced templates are restricted to the configured
Views folder.

[source,html]
.src/main/resources/views/home.jinja
----
include::{testsviewsJinjava}/resources/views/home.jinja[]
----

== Configuration

The renderer can be disabled with `micronaut.views.jinja.enabled=false`. Jinjava's configuration builder is exposed
under `micronaut.views.jinja.config.*`; for example, set `micronaut.views.jinja.config.trim-blocks=true` to trim
the first newline after a Jinja block.

=== Autoescape

By default, Jinjava HTML-escapes the output of `+{{ }}+` expressions. Templates do not need a manual `| e` filter
to HTML-escape untrusted values. For example, `+<h1>{{ message }}</h1>+` renders a `message` of `+<b>x</b>+` as
`+<h1>&lt;b&gt;x&lt;/b&gt;</h1>+`.

Earlier versions left autoescaping disabled. To retain that behaviour, explicitly set
`micronaut.views.jinja.autoescape` to `false`:

.application configuration
[configuration]
----
micronaut:
  views:
    jinja:
      autoescape: false
----

Trusted HTML can be marked with the `| safe` filter, and a block can switch autoescaping off with
`+{% autoescape false %} ... {% endautoescape %}+`. Only use these opt-outs for trusted content.

NOTE: With autoescaping enabled, do not also apply the `| escape` (or `| e`) filter to the same value. The value is
already escaped, so `| escape` escapes it a second time and `+&lt;+` is rendered as `+&amp;lt;+`.
